# RummikubSolver inference-server

Python + FastAPI + Ultralytics server that runs our own trained YOLOv11m
model (`best.pt`) locally. This replaces Roboflow's paid serverless API for
tile detection - the Android client sends it a photo, it sends back
bounding boxes. Everything else (auth, turn history) stays on the Node
`server/` - this is a separate service on purpose, it only knows about
detection.

## What's here

```
inference-server/
  requirements.txt   fastapi, uvicorn, ultralytics, pillow
  server.py           the whole server: loads best.pt once, exposes /detect + /health
  best.pt             the trained model weights (not generated by this server)
```

## Running it locally

1. `pip install -r requirements.txt`
2. Make sure `best.pt` is present in this folder (it should already be here -
   this server does not train or download it, only loads it).
3. `uvicorn server:app --host 0.0.0.0 --port 8001`
4. Check it's alive: `curl http://localhost:8001/health` should return
   something like `{"status":"ok","classes":53}`

`--host 0.0.0.0` (not `127.0.0.1`) matters - it's what lets the Android
emulator reach this process via `10.0.2.2`, the emulator's alias for "the
host machine's localhost".

## Endpoint

| Method | Path      | Body                     | Returns                                                    |
|--------|-----------|--------------------------|-------------------------------------------------------------|
| GET    | `/health` | -                        | `{ status: "ok", classes: <number of classes model knows> }` |
| POST   | `/detect` | `{ image: <base64 JPEG> }` | `{ predictions: [...], image: { width, height } }`         |

Each entry in `predictions` is:

```json
{
  "class": "R7",
  "confidence": 0.93,
  "x": 0.12,
  "y": 0.34,
  "width": 0.05,
  "height": 0.09
}
```

`x`/`y` are the top-left corner, `width`/`height` the box size - all
normalized to 0-1 against the image's own dimensions (given back in
`image.width`/`image.height`). This is deliberately simpler than Roboflow's
response shape (no `outputs[0].predictions.predictions` nesting, no
center-based coordinates) - `DetectionClient` on the Android side parses it
directly with no conversion math beyond clamping to `[0, 1]`.

## Notes

- The model is loaded once at process startup (`YOLO("best.pt")`), not per
  request - reloading a ~40MB PyTorch model on every call would make each
  request far slower than the actual inference.
- The Android app's default `DETECTION_SERVER_URL`
  (`http://10.0.2.2:8001/detect`) points at exactly this server, run on the
  same machine as Android Studio - same convention as the Node server's
  `APP_SERVER_URL`. A physical device needs a real reachable address there
  instead.
